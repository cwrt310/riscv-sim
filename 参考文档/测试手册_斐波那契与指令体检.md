# 测试手册：斐波那契与全指令体检（Qt 界面版）

> 日期：2026-09-05
> 用途：在 Qt 界面里逐项测试模拟器，每个测试都给出**预期结果**和**该看的灯**。
> 配套文件：仓库根目录 `tests/` 下 4 个 `.asm` 文件与本文档对应（`fib.asm` / `memory.asm` / `all19.asm` / `datapath_lights.asm`）。
> ⚠️ 本文档所有预期值都已用命令行版（Assembler + CPU 直跑）验证过，与界面无关——界面里结果必须一致。

## 怎么测

1. 启动模拟器，**把代码块整段复制**进左侧编辑区（或「文件 → 打开」选 `tests/` 里的文件）；
2. 先设速度：**看灯 → 填 `0.5`**（两秒一条）；只验结果 → 填 `20`（快速跑完）；
3. 点「▶▶ 运行」；
4. 对照下面的「预期结果」查寄存器表；对照「该看的灯」查数据通路图；
5. 单步模式同样适用：点「▶ 单步」逐条走，每一步看灯对不对。

**通用观察点**：日志区每拍打一行 `[N] 助记符`，图顶部显示「第 N 拍：指令（PC → 0x..）」。日志行数 = 实际执行条数，下面每个测试都给了这个数。

## 测试一：斐波那契 F(10) = 55（经典循环）

**代码**（= `tests/fib.asm`，就是 `tests/workload.txt` 的内容）：

```asm
# 斐波那契 F(10) = 55（迭代 + 倒计数循环）
addi x1, x0, 9
addi x2, x0, 0
addi x3, x0, 1
beq x1, x0, 24
add x4, x3, x2
addi x2, x3, 0
addi x3, x4, 0
addi x1, x1, -1
jal x0, -20
```

**预期结果**：

| 寄存器 | 值 | 含义 |
|---|---|---|
| x1 | `0x00000000` | 倒计数归零 |
| x2 | `0x00000022`（34） | F(9) |
| x3 | `0x00000037`（55） | F(10) |
| x4 | `0x00000037`（55） | 最后一轮的和 |

**执行条数**：日志应刷出 **58 行**（`[1]` ~ `[58]`）。

**该看的灯**：
- 前 3 条 `addi`：寄存器堆 + ALU + 写回总线亮；
- 每次 `beq`：上方虚线（PC 回路）亮；
- 每次 `jal x0, -20`：上方虚线 + 写回总线都亮（jal 要写返回地址）；
- 循环体反复走 → 灯**来回亮 9 轮**，这是看「运行时灯效」的最佳观察对象。

**怎么读这个程序**：`x1` 从 9 倒数，每轮循环做「`x4=x2+x3`；`x2=x3`；`x3=x4`」推进斐波那契；`x1` 减到 0 时 `beq` 跳 24 字节（= 6 条指令）到程序末尾结束；否则 `jal -20` 跳回 `beq` 再来一轮。

## 测试二：访存指令（sw/lw、sb/lb、sh/lh + 小端序）

**代码**（= `tests/memory.asm`）：

```asm
# 访存测试：sw/lw、sb/lb、sh/lh、小端序
addi x2, x0, 100
addi x5, x0, 42
sw x5, 0(x2)
lw x6, 0(x2)

addi x5, x0, -1
sb x5, 0(x2)
lb x7, 0(x2)

addi x5, x0, -2
sh x5, 2(x2)
lh x8, 2(x2)

addi x5, x0, 300
sh x5, 2(x2)
lh x9, 2(x2)

lui x5, 0x11223
addi x5, x5, 0x344
sw x5, 0(x2)
lb x10, 0(x2)
addi x2, x2, 1
lb x11, 0(x2)
```

**预期结果**：

| 寄存器 | 值 | 验证了什么 |
|---|---|---|
| x2 | `0x00000065`（101） | 基址 100 之后 +1 |
| x5 | `0x11223344` | `lui` + `addi` 拼出 32 位数 |
| x6 | `0x0000002A`（42） | **sw → lw 配对** |
| x7 | `0xFFFFFFFF` | **sb → lb 符号扩展**（存 0xFF，读回 -1） |
| x8 | `0xFFFFFFFE` | **sh → lh 符号扩展**（负数） |
| x9 | `0x0000012C`（300） | sh → lh 正数（符号位 0，不扩展） |
| x10 | `0x00000044`（68） | **小端序**：0x11223344 的最低字节 0x44 在最低地址 |
| x11 | `0x00000033`（51） | 次低字节 0x33 在下一个地址 |

**执行条数**：19 行日志。

**该看的灯**：
- `sw`/`sb`/`sh`：数据存储器亮，**写回总线不亮**（store 不写寄存器，这是最容易看错的一条）；
- `lw`/`lb`/`lh`：数据存储器 + 写回总线都亮，且写回线走「**内存**下引 → 绕回寄存器堆」那段；
- `lui`：只有写回总线亮，ALU 不亮。

> 注意：内存表目前只显示**代码段**（地址 0 ~ 程序末尾）。数据写到了地址 100+，表里看不到——**以寄存器读回的值为准**。

**代码**（= `tests/all19.asm`）：

```asm
# 19 条指令全体检：算术/逻辑/移位/比较/高位/分支/跳转/访存
addi x1, x0, 5
addi x2, x0, 10
add x3, x1, x2
sub x4, x2, x1
andi x5, x1, 3
```

**预期结果**（全部 19 条指令的验收表）：

|---|---|---|---|
| x1 | `0x00000005` | addi | 5 |

| x3 | `0x0000000F` | **add** | 5+10 |
| x4 | `0x00000005` | **sub** | 10-5 |
| x5 | `0x00000001` | **andi** | 5&3 |
| x6 | `0x0000000D` | **ori** | 5\|8 |
| x7 | `0xFFFFFFFA` | **xori** | 5^(-1) = -6 |
| x8 | `0x00000014` | **slli** | 5<<2 = 20 |
| x9 | `0x00000001` | **slti** | 5<10 真 |
| x10 | `0x00000001` | **sltiu** | 同上有符号无符号都真 |
| x11 | `0x12345000` | **lui** | 高 20 位 |
| x12 | `0x00000064` | addi | 基址 100 |

## 测试四：灯效专项（逐条慢放，看每组灯对不对）

**代码**（= `tests/datapath_lights.asm`）：

```asm
# 灯效专项：速度填 0.5，逐条看灯
addi x1, x0, 42
lui x2, 0x12345
addi x3, x0, 100
sw x1, 0(x3)
lw x4, 0(x3)
beq x1, x1, 8
addi x5, x0, 1
jal x0, 8
addi x6, x0, 2
```

**预期结果**：x1=`0x0000002A`、x2=`0x12345000`、x3=`0x00000064`、x4=`0x0000002A`（lw 读回刚 sw 的 42）；**x5 = 0**（被 beq 跳过）、**x6 = 0**（被 jal 越过）。

**执行条数**：9 条指令，跳过 2 条 → 日志 **7 行**。

**逐拍灯效对照表**（通用，覆盖全部 6 类指令）：

| 拍 | 指令 | 寄存器堆 | ALU | 数据存储器 | 写回总线 | 上方虚线(PC回路) |
|---|---|---|---|---|---|---|
| 1 | `addi x1, x0, 42` | ✓ | ✓ | | ✓（ALU 下引） | |
| 2 | `lui x2, 0x12345` | ✓（写目标） | ✗ | | ✓ | |
| 3 | `addi x3, x0, 100` | ✓ | ✓ | | ✓ | |
| 4 | `sw x1, 0(x3)` | ✓ | ✓ | ✓ | **✗（无写回！）** | |
| 5 | `lw x4, 0(x3)` | ✓ | ✓ | ✓ | ✓（内存下引） | |
| 6 | `beq x1, x1, 8` | ✓ | ✓ | | ✗ | ✓ |
| 7 | `jal x0, 8` | ✓（写 x0，照亮） | ✗ | | ✓ | ✓ |

**一句话记忆**：运算类亮「寄存器堆+ALU+写回」；lw 多亮数据存储器；sw 亮数据存储器但**写回不亮**；beq/bne 亮虚线；jal 虚线+写回都亮；lui 只写回。

## 附录 A：跳转偏移怎么手算（还没有标签跳转时的土办法）

现在的汇编器**还不支持标签**（`loop:` 这种），`beq`/`bne`/`jal` 的立即数要自己算。规则就一条：

> **立即数 = 目标地址 − 本条指令地址（字节）**。跳 1 条指令 = ±4。

数法：把指令从上到下编号，第 n 条在地址 `4n`。

| 想干什么 | 怎么填 |
|---|---|
| beq/bne 跳到下一条（等效不跳） | `4` |
| beq/bne 跳过 1 条 | `8` |
| beq/bne 跳过 N 条 | `4 × (N+1)` |
| jal 跳回第 n 条（往回） | `4n − 本条地址`（负数） |
| jal 跳到程序末尾结束 | 数出「末尾地址 − 本条地址」 |

**实例**（测试一的 `jal x0, -20`）：

```
第 1 条 addi 地址 0  ｜ 第 2 条 addi 地址 4  ｜ 第 3 条 addi 地址 8
第 4 条 beq  地址 12 ｜ 第 5 条 add  地址 16 ｜ 第 6 条 addi 地址 20
第 7 条 addi 地址 24 ｜ 第 8 条 addi 地址 28 ｜ 第 9 条 jal  地址 32
```

`jal` 在第 9 条（地址 32），想跳回第 4 条 `beq`（地址 12）：`12 − 32 = −20` ✓
`beq x1, x0, 24` 想跳到程序末尾（9 条指令 → 末尾地址 36）：`36 − 12 = 24` ✓

> 不放心就先单步：点「▶ 单步」看 PC 走到哪，跳错了马上知道，再改立即数。

## 附录 B：已发现的坑（测试时如果结果不对，先看这里）

| 现象 | 原因 |
|---|---|
| 寄存器值对但灯不动 / 只亮最后一条 | 用了旧 exe？确认重新编译过；源码已修（`repaint()`） |
| 输入 `addi x1, x0, 0x1234` 得到 564 不是 4660 | **汇编器立即数超 12 位不报错**，只留低 12 位（`& 0xFFF`）。`addi` 合法范围 -2048~2047 |
| 内存表看不到 sw 写的数据 | 内存表只显示代码段，数据段以寄存器读回为准 |
| 程序不结束 / 报未实现指令 | 跳转偏移算错了，跳到程序外面读到了 0 |
