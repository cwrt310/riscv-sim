# 开发踩坑记录（riscv-sim）

> 定位：把开发中踩过的坑按「现象 → 原因 → 解决」记下来，避免重蹈。按时间倒序。
> 姊妹文档：《调试方法论_一个bug的完整复盘.md》——本文档记「坑是什么」，那份记「怎么找到坑」。

## 一、数据通路可视化阶段（2026-09-05）

### 0. 运行时只亮最后一条指令的灯 ⭐ 最有代表性

- **现象**：点「运行」，8 条指令只看到最后一条该亮的灯；单步（手动一条条点）完全正常。
- **原因**：`setHighlightMask()` 里调的 `update()` **不是立刻重画**，而是往事件队列塞一张重绘申请单，Qt 会把连续多张**合并成一次**。8 拍改了 8 次 `m_mask`，`paintEvent()` 只被调 1 次，读到的是最后那次的值。单步正常是因为两次点击之间有空闲，事件循环来得及消化申请单。
- **解决**：`refreshUI()` 末尾加 `datapath->repaint()`（同步，立刻画完才返回）；顺带把内存表每拍 `new QTableWidgetItem` 改成复用单元格 `it->setText()`（减轻事件循环负担）。
- **教训**：**「代码执行了」≠「屏幕看得见」**。框架 API 凡涉及「何时生效」，必须确认同步还是异步——Qt 文档原话是 "`update()` … **schedules** a paint event"。
- **副产品**：加了每拍日志 `[N] 助记符` + 图顶部「第 N 拍：指令（PC → 0x..）」，以后同类怀疑一眼能分诊（详见方法论文档第四节）。

### 0b. `(pc/4) % 7` 的伪高亮

- **现象**：灯确实在动，但亮的部件和指令毫无关系。
- **原因**：用「第几条指令 → 第几个盒子」点灯。第 3 条指令亮"寄存器堆"纯粹因为它排第 3，无物理含义；而且**单周期 CPU 一条指令一拍走完全部部件**，不存在"这一拍处于第 3 阶段"（那是五级流水线的概念）。另外 `% 7` 前没有边界检查，PC 越界还会读到垃圾。
- **解决**：改成按 `opcode` 算「这条指令真的用到哪些部件」，位掩码同时点亮多个（`datapathMask()`）。
- **教训**：**做可视化前先说清「这个图在表达什么物理事实」**，说不清就是还没理解要画的东西。

### 0c. 把 WB（写回）画成一个盒子

- **现象**：7 个盒子一条直线 `PC→IF→ID→REG→EX→MEM→WB`，看着像五级流水线，不像单周期。
- **原因**：`WB` 不是部件（名词）而是动作（动词）——它是"把结果送回寄存器堆"这条**线**。画成盒子既虚构了硬件，又掩盖了真正的结构特征：**数据通路里有回路**（写回回路 + PC 跳转回路，第一版两条都缺）。
- **解决**：6 个部件排一行，两条回路分层走——写回总线走下方实线，PC 跳转走上方虚线（虚线 = 只在 beq/jal 时才有数据流）。
- **教训**：**画结构图先分清名词和动词**。名词画盒子，动词画线或标注；混在一起画，图就会撒谎。

### 0d. 毫秒调速是反直觉的

- **现象**：滑条填毫秒，数字越大越慢，用起来头疼。
- **解决**：换成 `QDoubleSpinBox`，单位改成 **「条/秒」**（0.2~50），数字越大越快，内部再 `1000/ips` 换算成毫秒喂 QTimer。
- **教训**：**给人看的单位要顺着直觉**，反比关系的量（周期 vs 频率）优先选正比那个。

## 二、Qt 界面阶段

### 1. 连续单步 → 未响应 → 窗口崩溃

- **现象**：程序（尤其只有 1 条指令时）执行完后继续点「单步」，界面卡死然后直接关掉。
- **原因**：单步没有边界检查。程序执行完 PC 已到末尾，再 `step()` 会去「程序末尾之外」取指令，读到 `0x00000000`（内存未初始化的垃圾），opcode=0 不是合法指令 → `execute()` 抛异常 → Qt 的按钮回调**不捕获异常** → 程序崩溃。
- **解决**：给 CPU 加 `finished()`（`pc_ >= progEnd_`），单步前先判断，执行完就提示并 `return`。
- **教训**：**写「按一下就动一下」的按钮，先想「连续点、点到尽头会发生什么」**。

### 2. 内存表固定 16 行，程序超过 16 条显示不全

- **现象**：内存表只显示 16 行，程序超过 16 条指令后面看不到。
- **原因**：`QTableWidget(16, 2)` 写死 16 行，`refresh()` 也固定循环 16 次。
- **解决**：初始 0 行，`load()` 里 `setRowCount(code.size())` 按程序大小设行数，`refresh()` 遍历 `rowCount()`。
- **教训**：**「显示窗口大小」≠「数据上限」**，别把显示写死。

### 3. windeployqt 报「No such file or directory」

- **现象**：`cd ..._Release` 报目录不存在，`windeployqt` 说 exe 不存在。
- **原因**：还没编译 Release 版，Release 目录根本没生成。
- **解决**：先在 Qt Creator 里切 Release 编译，再跑 `windeployqt`。

### 4. 构建配置只有 Debug，没有 Release

- **现象**：左下角切换器里只有 Debug。
- **原因**：项目默认只启用了 Debug 构建配置，Release 没勾选。
- **解决**：左侧「项目」→「构建」→ 勾选 Release。
- **澄清**：**构建套件（Kit）**= 编译器+Qt 版本（就一个，正常）；**构建配置**= Debug/Release 模式（Release 默认没启用）。两者别混。

### 4b. 未实现指令导致闪退

- **现象**：输入没实现的指令，界面直接关掉，不提示错误。
- **原因**：Assembler/CPU 遇到未知指令 `throw`，异常在按钮槽函数里抛出，Qt 不接管 → 崩溃。
- **解决**：`loadProgram()` / `onStepClicked()` / `onTimerTick()` 三处都包 `try-catch(const std::exception&)`，把 `e.what()` 打到日志。
- **教训**：**Qt 槽函数是「异常终点站」**，异常抛出槽函数就没人接了。凡是槽函数里调可能 throw 的后端代码，就得在槽里兜住。

## 三、命令行阶段（早期）

### 5. andi 立即数算错（运算符优先级）

- **现象**：`andi x5, x1, 3` 结果不对。
- **原因**：`(u32(imm)) & 0xFFF << 20` 漏括号，`<<` 优先级高于 `&`，先算了 `0xFFF << 20`。
- **解决**：`(u32(imm) & 0xFFF) << 20`。
- **口诀**：`&` 和 `<<` 连用，想「先截断再移位」就给 `&` 加括号。

### 6. beq PC 算错

- **现象**：跳转目标错位。
- **原因**：写成 `pc_ += imm - 4 + imm`（`+=` 且 imm 写了两次）。
- **解决**：`pc_ = pc_ - 4 + imm`（`step()` 里已 `pc_ += 4`，跳转要 `-4` 回到原址再加偏移）。

### 7. slti 符号错误

- **现象**：负数比较结果错。
- **原因**：`rf_.read(rs1) < imm` 是 u32 和 i32 比较，被当无符号。
- **解决**：有符号比较先转 `(i32)rf_.read(rs1) < imm`；无符号用 `u32(imm)`。

### 8. J 型立即数移位 off-by-one

- **现象**：jal 跳转目标错（+8 跳成 +4）。
- **原因**：拼回/拆开 J 型立即数时移位量写小 1（`<< n` 的 n 应等于「该片最低位的 bit 号」）。
- **解决**：`imm[20]<<20`、`imm[10:1]<<1`、`imm[11]<<11`、`imm[19:12]<<12`。
- **口诀**：`<< n` 里那个 n = 这一片最低位要去的 bit 号。

### 9. 中文乱码

- **现象**：控制台输出中文变乱码。
- **原因**：UTF-8 源码 vs GBK 控制台编码不匹配。
- **解决**：只影响显示不影响数据，忽略或用 `chcp 65001`。

### 9b. addi 立即数超 12 位被悄悄截断（不报错）

- **现象**：`addi x1, x0, 0x1234` 执行后 x1 = 564（0x234）而不是 4660（0x1234）。
- **原因**：汇编器 `(u32(imm) & 0xFFF) << 20` 直接把超出的高位砍掉，**不检查立即数范围**。0x1234 = 4660 > 2047（12 位有符号上限），被截成 0x234 = 564。
- **解决**：临时绕开——只写合法立即数（-2048 ~ 2047）；根治要等汇编器加范围检查（throw 而不是截断）。
- **教训**：**「跑通没报错」≠「结果对」**。用 `0x1234` 这种边界值测试时，先在纸上算一遍预期值，对不上就去查编码范围。

> 发现过程：写《测试手册》时验证程序发现预期 0x1234 实际是 0x234，顺藤摸瓜定位到汇编器。**测试程序本身反而帮硬件抓了个 bug**——这就是测试手册用「命令行版先验证预期值」的原因。

## 四、Git 阶段

### 10. Author identity unknown

- **解决**：`git config --global user.name/email`（Git Bash 和 WSL 是两套环境，各配各的）。

### 11. push 报 fetch first

- **原因**：本地和远程历史无关（建仓库时勾了 README）。
- **解决**：新私有仓库可安全 `--force`（有内容时慎用）；本地分支名不一致用 `git branch -M main`。

### 12. 误提交 build 产物（release/ 和 zip）

- **现象**：`release/` 目录和打包的 zip 进了版本库，仓库体积暴涨。
- **解决**：`git rm -r --cached release/`（`--cached` = 只从索引删、保留本地文件）+ 写 `.gitignore`；已进历史的话要 rebase 清。
- **教训**：**新项目第一次 commit 之前先写 `.gitignore`**。build 产物、exe、zip 一律不进库。
- **附带坑**：在 GitHub 网页上直接编辑 `.gitignore` 时中文输入法把 `*.zip` 打成了 `*。zip`（全角句号）→ 规则失效。**配置文件里的标点必须半角**。

## 五、按类型归纳（快速索引）

| 类型 | 坑号 | 共性教训 |
|---|---|---|
| **异步/时序** | 0 | 框架 API 涉及"何时生效"必查同步/异步 |
| **抽象建模错** | 0b、0c | 画图/建模前先说清表达的是什么物理事实；名词画盒子、动词画线 |
| **边界未检查** | 1、0b | 「按一下动一下」的按钮，先想连续点到尽头会怎样 |
| **写死常量** | 2 | 「显示窗口大小」≠「数据上限」 |
| **异常穿透** | 4b | Qt 槽函数是异常终点站，必须自己兜 |
| **运算符/位操作** | 5、8 | `&` 与 `<<` 连用加括号；`<< n` 的 n = 该片最低位的 bit 号 |
| **有无符号混用** | 7 | 有符号比较显式转 `(i32)` |
| **PC 语义** | 6 | `step()` 里已 `pc_ += 4`，跳转要先 `-4` |
| **工具链状态** | 3、4 | 「命令报错找不到文件」先确认那个文件到底生成过没有 |
| **人机界面** | 0d | 给人看的单位要顺着直觉 |
| **交互体验** | 0d、0 | 加自证机制（日志/计数器）比反复猜快得多 |
